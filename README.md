# Солянка

Мобильное Telegram Mini App для планирования продаж мерча, расчёта окупаемости артмаркетов и учёта постоянных полок. Белая и тёмная темы, красные акценты, профиль Telegram, плавающая навигация.

Приложение полностью статическое: HTML, CSS и JavaScript. Для работы не нужны сборка, Node.js, платные API, собственный сервер, удалённая база данных или ИИ. Python в примере ниже используется только как локальный сервер разработки.

## Что работает

- **Инвентарь:** категории и собственные названия, фотографии, количество и себестоимость за единицу, закупки с пересчётом средней себестоимости, обычные цены, свободные и распределённые остатки, списания.
- **Простой калькулятор:** общий прогноз продаж и две цели: возврат участия и закупки взятого мерча; та же сумма плюс заданный процент от вложений. Закупка товаров, оставшихся дома, в цель не входит.
- **Продвинутый калькулятор:** самостоятельные цены и закупочная стоимость в сценарии; ползунки цен и доли продаж. Изменение закупки в сценарии не меняет инвентарь.
- **Акции:** наборы до 10 разных позиций, количество каждой позиции, цена, прогноз количества наборов, общий контроль расходования товаров. Наборы учитываются в прогнозе раньше одиночных продаж; при пересечении составов порядок создания задаёт приоритет. После изменения прогноза недоступные наборы автоматически сокращаются.
- **Результат:** выручка, расходы, результат после всех вложений, прибыль с проданного, закреплённая компактная карточка с полосой окупаемости без изменения размеров при прокрутке. Обновление при движении ползунков.
- **Маркеты:** название, дата, адрес, резервирование выбранного мерча, сохранённые цены и себестоимость, редактируемый чеклист, частичные продажи и продажи постфактум, фактическая выручка, завершение по непроданным остаткам с учётом ранее внесённых продаж, повторение плана, отмена последней записи продаж. Завершённый маркет можно открыть снова при достаточном свободном запасе.
- **Полки:** размещение и возврат мерча, свои цены и целевой запас, даты проверки и аренды, продажи, комиссия, фактически оплаченная аренда, месячные отчёты и отмена последней записи. Проверки и даты показываются внутри приложения; системных уведомлений в закрытом приложении нет.
- **Первый запуск:** предупреждение о локальном хранении и необходимости резервных копий. После явного подтверждения отметка сохраняется на устройстве; предупреждение можно снова открыть в настройках. В демо оно автоматически не показывается.
- **Настройки:** авто / светлая / тёмная тема, резервная копия JSON с фото, проверка и восстановление копии, отдельное демо без сохранения деловых данных.

При добавлении товара вводятся количество и **себестоимость одной штуки**, например 40 × 120 ₽. Стоимость остатка (4 800 ₽) считается автоматически. Существующие товары, сохранённые планы и резервные копии сохраняют свои значения.

## Запуск на компьютере

В терминале из этой папки:

```sh
python3 -m http.server 4173
```

Открой `http://localhost:4173/`. Для демо — `http://localhost:4173/?demo=1`.

Открывать `index.html` двойным нажатием через `file://` не нужно: модулям и локальному хранилищу требуется веб-адрес.

## Публикация на GitHub Pages

1. Создай или выбери репозиторий. На GitHub Free для Pages нужен публичный репозиторий.
2. Загрузи **содержимое этой папки** в корень репозитория, включая папку `assets` и скрытый пустой файл `.nojekyll`. `index.html` должен оказаться непосредственно в корне.
3. В репозитории открой **Settings → Pages → Build and deployment → Source → Deploy from a branch**.
4. Выбери ветку с файлами, обычно `main`, и папку **/(root)**. Нажми **Save**.
5. Дождись публикации и скопируй HTTPS-адрес сайта из раздела Pages. Для проекта он обычно выглядит как `https://USERNAME.github.io/REPOSITORY/`.
6. Проверь обычный адрес и демо `?demo=1`. Все пути к ресурсам относительные: приложение работает и внутри пути репозитория.

При обновлении загружай изменённые исходники. У Service Worker меняй суффикс `CACHE` в `sw.js` при выпуске новой версии. Локальные товары и продажи хранятся отдельно от кеша ресурсов. Кеш разделён по пути размещения и содержит только файлы приложения; параметры запуска не создают лишних копий.

Официальная инструкция: [настройка источника публикации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Подключение к Telegram

1. Создай бота в [@BotFather](https://t.me/BotFather), если его ещё нет.
2. В настройках бота включи **Main Mini App** и укажи HTTPS-адрес опубликованного сайта. Можно также настроить **Menu Button** с тем же адресом.
3. Добавь название, описание и изображения приложения в BotFather.
4. Открой Mini App из профиля бота или его кнопки меню. Бот для запуска этого локального инструмента не нуждается в постоянно работающем обработчике сообщений.

Токен бота в код приложения или репозиторий добавлять не требуется. Приложение не обращается к Bot API и не отправляет сообщения от имени пользователя.

Создание: `/newbot` в BotFather → имя и свободный username с окончанием `bot`. Затем `/mybots → Bot Settings → Configure Mini App → Enable Mini App`.

Официальная документация: [запуск Main Mini App](https://core.telegram.org/bots/webapps#launching-the-main-mini-app), [кнопка меню](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button).

## Математика

Количество ожидаемых продаж каждой позиции: `floor(взято × общий процент / 100)`. Количество всегда целое. При 0% выручка нулевая и приложение объясняет необходимость изменить прогноз.

Выручка состоит из цены и количества наборов плюс одиночные продажи оставшихся ожидаемых единиц. Товар внутри набора повторно в одиночные продажи не попадает. Несколько акций используют единый запас.

В новых расчётах простого режима наценка распределяется с учётом категории и себестоимости. Ориентиры плавно зависят от квадратного корня себестоимости; дорогие товары получают меньшую относительную наценку. Подбор покрывает выбранную цель, пока это возможно в пределах рекомендаций. Цена не ниже себестоимости, округление вверх — 1 / 10 / 50 / 100 ₽. Если цель недостижима, отображается недостающая сумма. Ручные цены Про не ограничиваются. Исторические планы без `pricingModel` сохраняют прежнюю формулу; новые используют `category-v1`.

Это расчёт цен под введённый прогноз, а не прогноз рыночного спроса.

- **После всех вложений** = выручка − расходы на участие − закупка всего взятого мерча.
- **Прибыль с проданного** = выручка − расходы на участие − себестоимость только проданных вещей.
- **Плюс 25%** = цель `1,25 × (расходы на участие + закупка взятого мерча)`. Это процент от вложений, а не доля выручки.
- Фактические продажи рассчитываются по сохранённым ценам, с возможностью вручную указать выручку за запись. Себестоимость и количество проданных вещей при этом сохраняются.
- На полках вычитаются себестоимость проданного, сохранённая на момент записи комиссия и аренда, внесённая за выбранный месяц. Плановая аренда сама по себе не считается оплаченным расходом.

В версии 1 нет налогового расчёта, платёжного эквайринга, уведомлений вне приложения, командного доступа и учёта производственных партий по FIFO. Закупки усредняют себестоимость оставшегося товара; исторические снимки мероприятий сохраняются отдельно.

## Хранение и фотографии

Основные данные и фотографии сохраняются в **IndexedDB на устройстве**, настройки входят в то же сохранение. Если IndexedDB недоступна, текстовые данные сохраняются в `localStorage`, а добавление фото сообщает об ограничении. Дополнительно текстовая копия зеркалируется в **Telegram DeviceStorage**, если клиент поддерживает API 9.0+; этот механизм имеет лимит 5 МБ и не используется для фотографий. Ошибка зеркала не отменяет успешное основное локальное сохранение.

Фото преобразуются на устройстве в JPEG с длинной стороной до 800 пикселей и качеством 78%. Оригинал не сохраняется в приложении и не отправляется на сервер. Пустые карточки используют встроенные SVG-иллюстрации.

С сайта загружаются файлы приложения; дополнительно подключается официальный Telegram WebApp SDK с `telegram.org`. Аналитики, трекеров, удалённой обработки пользовательских расчётов и внешних шрифтов нет. После успешного первого открытия Service Worker сохраняет ресурсы для последующих запусков без сети там, где это поддерживается клиентом. Первый запуск требует подключения.

Обычная очистка медиакэша Telegram не описывается как гарантированное удаление всех данных миниаппы. Предупреждение сформулировано о риске потери локального сохранения при очистке данных миниаппы, переустановке клиента или смене устройства. Файл копии рекомендуется хранить вне кэша Telegram, например в приложении «Файлы» или на своём диске.

Автоматической синхронизации между устройствами нет. Очистка данных, переустановка клиента и ограничения ОС могут удалить локальное сохранение. Резервную копию можно скачать или передать через системное меню «Поделиться файлом», если оно доступно. Поведение скачивания и системного меню нужно проверить в целевых версиях Telegram iOS и Android.

Сайт и браузер вне Telegram имеют отдельное хранилище от Mini App. При изменении домена, пути размещения или бота заранее экспортируй копию и восстанови её в новом месте.

## Обновление 1.1 — мобильные сценарии

- Расчёт: мерч → акции → расходы и цель → итог. Шаг сохраняется с черновиком.
- Добавление товара: вид и название → количество и цены → необязательное фото.
- Создание полки: название и адрес → аренда и комиссия → даты. Разделы полки: мерч, отчёт, аренда.
- Маркет: обзор, план и продажи открываются отдельно.
- Отчёт о продажах: общее количество каждой позиции (включая наборы) → фактическая выручка → проверка. По умолчанию сумма считается по обычным ценам; скидки отражаются в общей выручке. При возврате к количеству автоматическая сумма пересчитывается, введённая вручную сохраняется.
- Наборы: одинаковые позиции объединяются. Запас и лимит прогноза показываются отдельно; редактирование сохраняет приоритет акции. Например, 11 взятых брелков дают 5 пар, при прогнозе 60% — 3 пары.
- Удаление товара убирает его из инвентаря и черновика и списывает свободный остаток. Активный резерв защищён от удаления. Техническая запись товара остаётся в резервной копии для старых продаж и отмены; это не полное удаление всех данных о товаре.
- Удаление маркета освобождает резерв и удаляет отчёт, но не возвращает проданный мерч.
- Нулевое значение очищается при фокусе числового поля; пустое исходное нулевое поле восстанавливается при выходе. На сенсорном экране свайп вне поля снимает фокус с клавиатуры.
- Более крупные тексты, холодный красный, голубые и зелёные акценты; даты на узком экране занимают отдельную строку.

Проверка версии 1.1: 25 автоматических тестов расчётов, остатков, удаления, сохранения и кеша; проверка синтаксиса JavaScript. Браузерная проверка новой вёрстки не выполнена: доступ к локальному предпросмотру отклонён. Клавиатуру и системный выбор даты нужно проверить в Telegram на iPhone и Android.


## Обновление 1.2 — визуальный выбор

Стартовый экран — «Мои запасы». Калькулятор сначала предлагает простой или про-режим. В простом режиме график, три цели и процент продаж находятся только в итогах; в про все ручные настройки собраны вместе с живым графиком. Мерч, состав набора, продажи и перемещения на полку выбираются карточками с изображениями и кнопками −/+. Добавлены приветствие с персонажем, пять PNG, удаление полки без удвоения остатков и короткое подтверждение завершения маркета. Пожелания по числу наборов сохраняются при изменении прогноза.

В блоке окупаемости затраты = участие + закупка всего взятого мерча; прибыль = выручка − эти затраты. Это результат после всех вложений, включая оставшийся непроданный мерч.

Версия 1.2: 35 автоматических тестов прошли. Проверены шаблоны экранов, расчёты, сохранение и кеш; браузерная и телефонная проверка ещё не выполнены из-за ранее отклонённого доступа к локальному предпросмотру.
